Правила по этапам

Короткое ядро читается всегда, карточка текущего этапа — только на этом этапе, модули — только если они нужны проекту. Меньше правил в работе — меньше ошибок.

Профили S/M/L

Малый проект ведёт пять страниц, а не пятнадцать. На методику — не больше 10–15 % часов проекта.

Данные заказчика и ТЗ

Запрос данных с ответственными и сроками, интервью, реестр требований с источниками и критериями приёмки, ТЗ-лайт или по структуре ГОСТ 34.602-2020, утверждение и изменения только по запросу.

Решения по месту

Методика — базовое положение. Каждый спорный вопрос — с вариантом «по методике» и вариантом оптимизации процесса. Персональные данные — в ИИ не уходят: ИИ работает с шаблоном, значения подставляет код.

Идея в трёх фразах

Раскладывать один раз

Новый источник сразу разносится по коротким живым страницам проекта. Дальше нейросеть читает их, а не перерывает сотни сырых файлов.

Копить, а не искать

Время и токены уходят на ведение знаний, а не на повторный поиск. С каждым источником проект становится богаче.

Доказывать успех

«Сделано» ставится только со ссылкой на проверку. «Сделано у нас» и «принято заказчиком» — разные отметки.

Откуда это

  • Andrej Karpathy, LLM Wiki: три слоя знаний, операции «приём — вопрос — сверка».
  • Jiayuan Zhang, Karpathy-Inspired Claude Code Guidelines — по наблюдениям Andrej Karpathy: думать до работы, простота, хирургические правки, проверяемая цель.
  • Andrej Karpathy, autoresearch: автономный цикл по программе с одной метрикой.
  • Практика ARARAT33: никакого фальшивого успеха, доказательства готовности.
  • Собственный опыт консалтинговых проектов по автоматизации: вопросы по одному, решения с причинами, подтверждения заказчику.
  • CNSC, ONR, US NRC, Considerations for developing AI systems in nuclear applications (2024), и отчёт ONR о регуляторной песочнице по ИИ: автономность и последствия, «вероятность отказа ИИ = 1», безопасное состояние.
  • UC Berkeley, MAST: почему ломаются мультиагентные системы. PMI, PMBOK: устав, изменения, риски, закрытие.
  • Доклады конференции CNews «Технологии искусственного интеллекта» (22.09.2026): ступени автономии, эталонные случаи, метрики процесса.

Три слоя проекта

Проект/
├── Источники/      ← входящее как есть: нейросеть только читает
│   └── _резюме/
├── INDEX.md        ← оглавление: его читают первым
├── ЖУРНАЛ.md       ← хронология: только дописывается
├── СТАТУС.md  ПЛАН.md  РЕШЕНИЯ.md  ВОПРОСЫ.md  ГЛОССАРИЙ.md   ← живые страницы
└── AGENTS.md       ← правила проекта для любых агентов

Три операции

1. Приём источника

Стенограмма, письмо или документ кладётся в «Источники». Нейросеть пишет резюме и разносит новое по страницам: решения, вопросы, статус, план. Противоречия со старым выносит вопросом, а не исправляет молча. Затем обновляет оглавление и делает запись в журнале. Большой источник после этого целиком больше не читается.

2. Вопрос

Ответ строится по живым страницам со ссылками на них. Ценный ответ сохраняется новой страницей, и знание копится.

3. Сверка — раз в неделю

Нейросеть ищет противоречия, устаревшее, «сделано» без доказательства, вопросы без движения, битые ссылки. Результат — отчёт; правки вносятся после одобрения человеком.

Честный статус

ОтметкаКогда ставится
сделаноесть ссылка на доказательство: скриншот, номер выполнения, файл, отчёт прогона
принятозаказчик подтвердил: кто, когда, ссылка на письмо или стенограмму
регресссломалось — отметка снимается, в журнал пишется инцидент

Замер «до». Пока процесс ручной, снимается базовая линия. Четыре метрики вместе: сквозное время, доля принятых с первого раза, пропущенные эскалации, минуты проверки на единицу результата. Готовность («внедрено») и результат (эффект против замера) — разные вещи.

Четыре правила исполнителя

  1. Думать до работы. Допущения вслух. Если задачу можно понять по-разному — показать варианты. Непонятно — спросить.
  2. Сначала простота. Минимум, решающий задачу. Ничего «на будущее».
  3. Хирургические правки. Трогать только то, что требует задача.
  4. Проверяемая цель. Критерии успеха — до начала работы; план — «шаг → проверка».

ИИ внутри решения новое в 2.0

Нужен ли здесь ИИ

Для каждого шага: можно ли его убрать → регламент → автоматизация без LLM → ассистент → агент с подтверждением. ИИ — только если выигрывает.

Паспорт ИИ-шага

Ступень автономии 0–5, кто проверяет, ограничители, безопасное состояние, порог «не уверен». Деньги и медицина — не выше «с подтверждением человека».

Отказ = 1

Для важных шагов проектируем так, будто ИИ уже ошибся: доверие держится на архитектуре, а не на просьбе в промпте.

Проверка до агента

30–50 эталонных случаев на каждый ИИ-шаг, прогон после каждой правки, параллельный прогон с ручным процессом.

Закон, риски, закрытие новое в 2.0

  • Закон и персональные данные — раздел в каждом проекте: где хранятся данные, уходят ли во внешние модели, согласия, уведомления, порядок при утечке.
  • Устав с ожидаемыми выгодами и владельцем эффекта у заказчика; всё сверх границ — только через запрос на изменение.
  • Реестр рисков с еженедельным обзором; протокол закрытия: цели, критерии, выгоды, передача, уроки; план вывода системы из эксплуатации.
  • Опора на ISO 20700, ГОСТ Р ИСО 21502-2024, ГОСТ Р ИСО 31000-2019, ISO/IEC 19510 (BPMN), ГОСТ Р ИСО/МЭК 42001-2024 — опора, а не заявление о сертификации.

С любой нейросетью

  • Агенты с доступом к файлам — Codex, Claude Code, Cursor, Gemini CLI, Qwen Code, Aider: файл правил AGENTS.md в корне проекта, дальше агент ведёт оглавление и журнал сам.
  • Чат без доступа к файлам — ChatGPT, Claude.ai, Gemini, DeepSeek, GigaChat, YandexGPT: правила вставляются в инструкцию проекта, в начале сессии загружаются оглавление, статус и конец журнала. Нейросеть возвращает правки текстом, человек переносит их в файлы.
  • Несколько моделей сразу: живые страницы правит одна ведущая модель, остальные работают по заданиям и проверяют.

Быстрый старт за 15 минут

  1. Скачайте шаблоны с GitHub и скопируйте папку templates в проект.
  2. Заполните цель и границы в AGENTS.md и устав в ПЛАН.md.
  3. Положите в «Источники» всё, что уже есть по проекту.
  4. Попросите нейросеть принять источники по одному — готовый промпт в папке prompts.
  5. Каждую сессию начинайте с промпта «начало сессии», раз в неделю проводите сверку.
